# Plan — `js`: the page bootstrap takes the wasm URL; the Go service worker goes away

Master plan: [PWA_ARTIFACTS_MASTER_PLAN.md](https://github.com/webtyp/app/blob/main/docs/PWA_ARTIFACTS_MASTER_PLAN.md),
decisions D-PWA-4 and D-PWA-5.

## Why

- **D-PWA-5:** in release builds `sitec` names the binary by its content hash
  (`client.3f9a1c2b.wasm`) so the browser and the service worker never mix versions. Today
  `PageBootstrap()` has `/client.wasm` hard-coded, so the bootstrap cannot load a hashed binary.
- **D-PWA-4:** the shell service worker is a short `sw.js` generated by `webtyp/pwa`.
  `js.ServiceWorker` would produce a second file with the same name, it loads the whole page binary
  inside the worker, and nobody uses it (only a comment in `goflare-demo`). Worse, `js_wasm.go`'s
  `init()` registers three global functions (`__webtyp_sw_install`, `__webtyp_sw_activate`,
  `__webtyp_sw_fetch`) in **every** `client.wasm` that imports `js`: dead code shipped to every user.

## Design gate

1. **Prior art.** Vite and webpack inject the hashed entry URL into the HTML/bootstrap they emit
   (`<script type="module" src="/assets/index-3f9a1c2b.js">`); Go's own `wasm_exec.html` takes the
   wasm path as a literal the author edits; TinyGo's examples do the same. The bundler knows the
   name, so the bootstrap takes it as a parameter.
2. **Novice-name test.** `js.PageBootstrap(wasmURL)` — "the page bootstrap for this wasm URL".
   `js.DefaultWasmURL` — "the default wasm URL" (`/client.wasm`, development).
3. **Complexity ledger.** Concepts −3 (`ServiceWorker`, `ServiceWorkerHandler`, `Request`) +1
   (`DefaultWasmURL`). Ways to make a service worker: 2 → 1 (`webtyp/pwa`).
4. **Where it belongs.** The URL is decided by the asset compiler, so it is a parameter here.
5. **What it deletes.** `ServiceWorker`, `ServiceWorkerHandler`, `Request`, `swHandler`,
   `js_wasm.go` entirely, the `ServiceWorker` tests, the README and ARCHITECTURE sections about it.

## Stage 1 — `js.go`

1. Export the constant: `const DefaultWasmURL = "/client.wasm"` (replaces unexported
   `defaultWasmURL`), doc comment: "where the development build serves the page binary; release
   builds pass the hashed name sitec emits".
2. `func PageBootstrap(wasmURL string) *Script`: same body, using `wasmURL` in both `fetch(...)`
   calls. An empty `wasmURL` is a programming error and panics, the same way `Script.validate()`
   already panics on a bad name: `panic(errEmptyWasmURL)` with
   `const errEmptyWasmURL = "js: PageBootstrap needs the wasm URL (js.DefaultWasmURL in development)"`.
   No silent fallback to `DefaultWasmURL`.
3. Delete `Request`, `ServiceWorkerHandler`, `swHandler`, `ServiceWorker`. Update the `SetRuntime`
   comment ("PageBootstrap and WebWorker embed").
4. Delete `js_wasm.go`. If `webtyp.com/context` or `webtyp.com/fetch` become unused in `js.go`, drop
   the imports and run `go mod tidy`.
